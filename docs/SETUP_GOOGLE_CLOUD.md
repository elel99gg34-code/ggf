# Google Cloud 설정 가이드

이 앱이 유튜브 계정을 읽고 고치려면 Google Cloud 프로젝트가 하나 필요해.
한 번만 해두면 된다.

읽는 사람이 둘 중 누구냐에 따라 볼 곳이 다르다.

- **앱을 만들어 지인에게 나눠주는 사람** → [A. 배포자용](#a-배포자용) 전체
- **받은 앱을 쓰는데 할당량이 부족한 사람** → [B. 사용자용](#b-사용자용-내-할당량-따로-쓰기)

---

## 먼저 알아야 할 것: 할당량은 프로젝트 단위다

유튜브 API는 **Google Cloud 프로젝트 하나당 하루 10,000유닛**이다.
돈을 내고 늘릴 수 없다 (신청은 가능하지만 개인 용도로는 거의 승인되지 않는다).

그런데 읽기는 1유닛인데 **쓰기는 전부 50유닛**이다.

| 작업 | 유닛 |
|---|---|
| 구독 목록 500개 읽기 | 10 |
| 좋아요 영상 1,000개 읽기 | 20 |
| 구독 취소 1건 | **50** |
| 재생목록에 영상 1개 넣기 | **50** |

즉 **하루에 가능한 쓰기 작업은 200번**이 물리적 상한이다.

여기서 중요한 함정: **여러 사람이 같은 프로젝트를 쓰면 그 10,000유닛을 나눠 쓴다.**
5명이 쓰면 1인당 2,000유닛, 하루 40번이다. 그래서 앱에 "내 client_secret.json 등록"
기능이 있고, [B](#b-사용자용-내-할당량-따로-쓰기)가 그 방법이다.

## A. 배포자용

### 1. 프로젝트 만들기

1. https://console.cloud.google.com/ 접속
2. 상단 프로젝트 선택 → **새 프로젝트**
3. 이름은 아무거나 (예: `ytorganizer`) → **만들기**

### 2. YouTube Data API v3 켜기

1. 왼쪽 메뉴 → **API 및 서비스** → **라이브러리**
2. `YouTube Data API v3` 검색 → **사용**

### 3. OAuth 동의 화면 — 여기가 제일 중요하다

1. **API 및 서비스** → **OAuth 동의 화면**
2. User Type: **외부(External)** → 만들기
3. 앱 정보 입력
   - 앱 이름: `YTOrganizer` (지인들이 로그인할 때 이 이름을 본다)
   - 사용자 지원 이메일 / 개발자 연락처: 본인 이메일
4. **범위(Scopes)** 단계 → **범위 추가 또는 삭제**에서 아래 하나를 체크
   ```
   https://www.googleapis.com/auth/youtube
   ```
   이 하나면 읽기·쓰기가 다 된다. `youtube.force-ssl`(댓글·자막까지)은 필요 없으니
   체크하지 마라 — 권한은 적을수록 좋고, 심사에서도 설명할 게 늘어난다.
5. **테스트 사용자** 단계는 일단 넘어간다.
6. 마지막으로 **반드시 할 일**: 동의 화면 요약 페이지에서
   **「앱 게시」 → 프로덕션으로 푸시**를 누른다.

> ### ⚠ 「게시」를 안 하면 생기는 일
>
> 동의 화면이 **테스트** 상태로 남아 있으면 **리프레시 토큰이 7일 만에 만료된다.**
> 지인들이 **매주 다시 로그인**해야 한다는 뜻이다. 문의가 제일 많이 들어오는 원인이니
> 꼭 프로덕션으로 바꿔라.
>
> 게시해도 **심사(verification)를 받는 건 아니다.** 심사 없이 게시하면:
> - 로그인할 때 "이 앱은 Google에서 확인하지 않았습니다" 경고 화면이 뜬다 (넘길 수 있다)
> - 이 프로젝트로 로그인할 수 있는 사람이 **평생 100명**으로 제한된다 (리셋 불가)
>
> 지인 몇 명에게 나눠주는 용도라면 이 상태로 충분하다.

### 4. OAuth 클라이언트 ID 만들기

1. **API 및 서비스** → **사용자 인증 정보** → **사용자 인증 정보 만들기**
   → **OAuth 클라이언트 ID**
2. 애플리케이션 유형: **데스크톱 앱** ← 반드시 이걸로
3. 이름은 아무거나 → **만들기**
4. **JSON 다운로드**

> 「웹 애플리케이션」으로 만들면 로그인이 `redirect_uri_mismatch` 오류로 실패한다.
> 이 앱은 그 실수를 감지하면 원인을 알려주지만, 처음부터 데스크톱 앱으로 만드는 게 낫다.

### 5. 앱에 넣고 빌드

받은 JSON 파일 이름을 `client_secret.json`으로 바꿔서 `packaging/` 폴더에 넣는다.

```
packaging/client_secret.json
```

그다음 `packaging/build.bat`을 더블클릭하면 이 파일이 exe 안에 포함된다.

> **이 파일을 깃허브에 올리지 마라.** `.gitignore`에 이미 넣어뒀다.
> 다만 데스크톱 앱의 client_secret은 Google도 비밀로 취급하지 않는다 —
> exe에서 추출되더라도 loopback 리디렉션 때문에 남의 계정을 건드릴 수 없다.
> 공개 저장소에 두지 않는 건 남이 내 할당량을 쓰는 걸 막기 위해서다.

### 6. 지인에게 전달할 때

같이 알려줄 것 두 가지:

1. 설치할 때 **"Windows의 PC 보호" 경고**가 뜬다 → 추가 정보 → 실행
2. 첫 로그인에서 **"확인되지 않은 앱" 경고**가 뜬다 → 고급 → (앱 이름)(으)로 이동

자세한 화면 설명은 `USER_GUIDE.md`에 있다.

## B. 사용자용: 내 할당량 따로 쓰기

앱에서 "오늘 할당량을 다 썼어"가 자주 뜬다면, 다른 사람과 같은 프로젝트를
나눠 쓰고 있기 때문이다. 자기 프로젝트를 만들면 **하루 10,000유닛을 혼자** 쓴다.

1. 위 [A의 1~4단계](#1-프로젝트-만들기)를 그대로 한다 (본인 계정으로).
   - 3단계에서 **테스트 사용자**에 본인 이메일을 추가하면 게시하지 않아도 된다.
     단 이 경우 **7일마다 다시 로그인**해야 한다. 귀찮으면 게시까지 해라.
2. 받은 JSON 파일을 준비한다.
3. 앱 실행 → **설정** 탭 → **내 client_secret.json 등록** → 파일 선택
4. **연결 끊기** → **유튜브 계정 연결** (새 설정으로 다시 로그인)

설정 탭의 "API 설정" 줄이 **내 프로젝트**로 바뀌면 성공이다.

## 자주 겪는 문제

| 증상 | 원인과 해결 |
|---|---|
| `redirect_uri_mismatch` | 클라이언트를 「웹 애플리케이션」으로 만들었다. 「데스크톱 앱」으로 다시 만들어라. |
| 일주일마다 로그인이 풀린다 | 동의 화면이 테스트 상태다. 프로덕션으로 게시해라. |
| `access_denied` | 동의 화면이 테스트 상태인데 그 계정이 테스트 사용자에 없다. 추가하거나 게시해라. |
| 할당량이 금방 바닥난다 | 프로젝트를 나눠 쓰는 중이다. [B](#b-사용자용-내-할당량-따로-쓰기)를 해라. |
| "확인되지 않은 앱" 경고 | 정상이다. 심사를 안 받은 상태라 그렇다. 고급 → 이동으로 넘어간다. |
| 100명이 넘었다 | 프로젝트당 평생 제한이고 리셋이 안 된다. 심사를 받거나, 각자 [B](#b-사용자용-내-할당량-따로-쓰기)로 자기 프로젝트를 쓰게 해라. |
