# YTOrganizer 사용 설명서

구독 채널과 재생목록을 한 번에 정리하는 프로그램이야.

---

## 1. 설치

`YTOrganizer-Setup.exe`를 실행한다. 관리자 권한은 필요 없다.

### "Windows의 PC 보호" 파란 창이 뜬다면

정상이다. 코드 서명 인증서(연 20~40만 원)를 사지 않은 프로그램은 전부 이 경고가 뜬다.

1. **추가 정보** 클릭
2. **실행** 클릭

백신이 막는 경우도 드물게 있는데, 파이썬으로 만든 프로그램을 압축해 배포하면
생기는 흔한 오탐이다. 예외로 등록하면 된다.

### 설치되는 위치

| 무엇 | 어디 |
|---|---|
| 프로그램 | `%LOCALAPPDATA%\Programs\YTOrganizer` |
| 내 데이터(로그인 정보·캐시·설정) | `%APPDATA%\YTOrganizer` |

프로그램을 제거해도 데이터는 남는다. 다시 깔면 로그인과 캐시가 그대로 살아난다.
완전히 지우려면 `%APPDATA%\YTOrganizer` 폴더를 직접 삭제해라.

## 2. 첫 실행

### 계정 연결

1. 앱을 켜면 **설정** 탭이 열린다.
2. **유튜브 계정 연결** 클릭 → 브라우저가 열린다.
3. 정리하려는 유튜브 계정으로 로그인.

#### "Google에서 확인하지 않은 앱입니다" 경고

이것도 정상이다. Google 심사를 받지 않은 개인 앱이라 그렇다.

1. **고급** 클릭
2. 맨 아래 **YTOrganizer(으)로 이동(안전하지 않음)** 클릭

> 걱정된다면: 이 앱은 유튜브 권한만 요청하고(메일·드라이브 접근 없음),
> 로그인 정보는 윈도우 자격 증명 관리자에 저장된다. 인터넷으로 나가는 건
> 유튜브 API뿐이다.

4. 권한 허용 → 브라우저에 "인증됐어"가 뜨면 창을 닫는다.

### 새로고침

연결했으면 오른쪽 위 **새로고침**을 누른다. 구독·재생목록·영상 정보를 한 번에 받아온다.

구독 500개 기준 1분쯤 걸리고 **500유닛 정도** 쓴다. 대부분은 채널별 최신 업로드를
확인하는 데 들어간다(휴면 채널 판정에 필요하다). 이게 아깝다면 설정에서
"동기화할 때 채널별 최신 업로드도 확인"을 끄면 동기화가 20유닛 아래로 떨어진다.

한 번 받아두면 **화면에서 뭘 하든 유닛을 쓰지 않는다.** 실제로 유튜브를 고칠 때만 쓴다.

---

## 3. 할당량 — 이것만 이해하면 된다

상단에 항상 떠 있는 숫자다.

```
남은 유닛 9,450 / 10,000     쓰기 작업 약 177건 가능
```

- 유튜브가 정한 하루 한도가 **10,000유닛**이다. 돈 내고 늘릴 수 없다.
- **읽기는 거의 공짜**(1유닛), **고치는 건 건당 50유닛**이다.
- 그래서 **하루에 200번**까지만 고칠 수 있다. 태평양시 자정(한국 시간 오후 4~5시)에 리셋된다.

### 하루에 안 끝나면?

알아서 나눠서 한다. 예를 들어 영상 500개를 재생목록로 분류하면 25,000유닛이라
사흘이 걸리는데, 앱이 오늘 몫만 처리하고 멈춘 뒤 다음 날 이어서 한다.
**실패가 아니라 일시정지**다. 작업 탭에서 "할당량 대기"로 보인다.

## 4. 기능

모든 "고치는" 작업은 **실행 전에 확인 창**이 뜬다. 무엇이 바뀌는지, 몇 유닛이 드는지,
며칠 걸리는지 표로 보여준다. 거기서 **실행**을 눌러야 실제로 바뀐다.

### 구독 정리

안 보는 채널을 찾아준다.

- **오래 안 올라옴** — 지정한 기간(기본 12개월) 동안 새 영상이 없는 채널
- **채널 사라짐** — 폐쇄됐거나 이미 구독이 끊긴 채널
- **이름 바뀜** — 예전 이름과 달라진 채널 (내가 구독한 그 채널이 맞는지 확인용)

체크 → **선택한 채널 구독 취소**.

> 유튜브 추천을 직접 조작하는 API는 없다(시청 기록도, "관심 없음"도 비공개다).
> 추천을 바꾸는 가장 확실한 방법이 구독 정리다.

### 재생목록

왼쪽에서 재생목록을 고르면 문제 항목을 찾아준다.

- **삭제·비공개** — 영상이 사라져 재생목록에 껍데기만 남은 항목
- **중복** — 같은 영상이 두 번 이상 들어간 것

**정렬**도 된다(업로드순·제목순·길이순·채널순). 다만 순서 변경은 항목당 50유닛이라
100개짜리를 통째로 정렬하면 5,000유닛이다. 앱이 **이미 제자리인 항목은 건드리지 않아서**
실제로는 훨씬 적게 든다. 확인 창에 "전부 옮기면 얼마였는데 얼마만 썼다"가 나온다.

### 자동 분류

좋아요 누른 영상을 주제별 재생목록으로 나눈다.

1. 대상 고르기 (좋아요 전부 / 재생목록에 없는 것만)
2. **분류해보기** — 0유닛이다. 결과만 보여준다.
3. 표에서 영상별로 어디로 갈지, 왜 그렇게 판단했는지 확인
4. 마음에 안 드는 줄은 체크 해제
5. **재생목록 만들기**

기본은 **규칙 기반**이라 공짜고 인터넷 없이도 된다. 키워드·채널·길이·카테고리로 판단한다.
같은 이름의 재생목록이 이미 있으면 새로 만들지 않고 거기 넣는다.
이미 들어 있는 영상은 건너뛴다 — **두 번 돌려도 중복이 안 생긴다.**

규칙을 고치고 싶으면 설정 → **기본 규칙을 파일로 내보내기** → `rules.yaml`을 편집하면 된다.

#### AI 분류 (선택)

Claude API 키가 있으면 더 똑똑하게 나눈다. 규칙에 없는 주제도 알아서 찾아낸다.

설정 → AI 분류에서 키를 넣고 체크. 영상 500개 분류에 **$0.5 내외**다.
키가 없거나 오류가 나면 조용히 규칙 기반으로 돌아간다.

### 작업

지금까지 한 일과 진행 상황이다.

- **할당량 대기** = 멈춘 게 아니라 내일 이어서 한다. **멈춘 작업 이어서 하기**로 지금 재개할 수도 있다.
- **선택한 작업 되돌리기** = 그 작업을 반대로 실행한다.

> 되돌리기도 유닛을 쓴다. "취소"가 아니라 "반대 작업을 한 번 더 하는 것"이라
> 구독 50개를 취소했다면 되돌릴 때도 2,500유닛이 든다. 확인 창에 비용이 나온다.
>
> 되돌릴 수 없는 것도 있다: **재생목록 삭제**는 복원되지 않는다(항목 순서와 추가 시각이
> 사라진다). 그래서 실행 전에 크게 경고한다.

## 5. 문제 해결

| 증상 | 해결 |
|---|---|
| 할당량이 금방 바닥난다 | 다른 사람과 같은 API 설정을 나눠 쓰는 중이다. `SETUP_GOOGLE_CLOUD.md`의 B를 보고 내 프로젝트를 등록해라. |
| 일주일마다 로그인이 풀린다 | 앱을 준 사람에게 "OAuth 동의 화면을 프로덕션으로 게시해달라"고 전해라. |
| 새로고침이 중간에 멈춘다 | 할당량이 떨어진 거다. 받은 데이터는 남아 있으니 다음 날 다시 누르면 이어서 받는다. |
| 구독 취소했는데 목록에 그대로다 | 새로고침을 눌러라. 화면은 마지막으로 받아온 상태를 보여준다. |
| 실행했는데 아무 창도 안 뜬다 | `%APPDATA%\YTOrganizer\ytorg.log`를 확인하거나 앱을 준 사람에게 보내라. |
| 분류가 마음에 안 든다 | 설정에서 규칙 파일을 내보내 직접 고치거나, AI 분류를 켜봐라. |
| 처음부터 다시 하고 싶다 | `%APPDATA%\YTOrganizer` 폴더를 삭제하면 초기화된다. 유튜브 계정은 건드리지 않는다. |

### 명령줄로도 쓸 수 있다

설치 폴더에 `YTOrganizer-cli.exe`가 같이 들어 있다. 화면에 결과를 출력하는
버전이라 문제를 진단할 때 쓴다 (평소 쓰는 `YTOrganizer.exe`는 창만 띄운다).

설치 폴더에서 명령 프롬프트를 열고:

```
YTOrganizer-cli.exe status        # 할당량과 현황
YTOrganizer-cli.exe demo          # 가짜 계정으로 동작 시연 (내 계정 안 건드림)
YTOrganizer-cli.exe subs          # 구독 정리 미리보기
YTOrganizer-cli.exe subs --apply  # 실제로 실행
```

`--apply`를 붙이지 않으면 **절대 아무것도 바뀌지 않는다.**

앱이 이상하게 동작하면 `YTOrganizer-cli.exe demo`를 먼저 돌려봐라.
가짜 계정으로 전체 기능을 돌려보는 거라 내 유튜브 계정은 건드리지 않고,
프로그램 자체에 문제가 있는지 아니면 계정/네트워크 문제인지 가려낼 수 있다.
